# 视频画风由第一张图决定——文生图最佳档图作为 H3 图生视频首帧参考（双参考图 × 0.4/0.6MP，5s 含原生音频）

中文 | [English](README.en.md)

## 一分钟看懂

| 问题 | 做法 | 结果 |
|---|---|---|
| 视频画风从哪来 | 把一张真人感图、一张动漫图分别作为视频第一帧，提示词与随机种子保持一致 | 画风完全由第一帧图决定：真人感图出真人 cos 感视频，动漫图出赛璐璐动漫视频，提示词无法改变——风格在选定参考图时已经锁定 |
| 提高视频分辨率值不值 | 同一张参考图分别在 0.4MP 与 0.6MP 两档生成视频 | 生成耗时由 70.4s 增至 125.6s，提升集中在背景细节（桁架、光斑、蕾丝纹理），人物主体两档均稳定——高档位只在需要背景细节时值得付出 |
| 人物全程稳不稳 | 对照 4 条成片检查角色要素 | 双马尾、水手服、配色全程一致，无换脸、无服装漂移——本实验时长内未出现角色退化 |

> 表中 MP（megapixel，兆像素）是画面总像素量的单位：档位越高，画面越大、细节越多，生成耗时也越长。

## 实验设置

本实验是 [t2i-res-sweep](../t2i-res-sweep/) 的下游验证：取两个文生图模型各自 0.6MP 的最佳档图（Z-Image Turbo 微写实、Flux 2 Klein 9B 动漫），作为 MiniMax H3 图生视频（fl2va，即由首帧图与文字提示生成视频）的首帧参考图，每条参考图分别在 0.4MP（544×736）与 0.6MP（672×896）两档生成视频，共 4 条。四条视频的提示词、随机种子、采样配置完全一致，差异只来自被对比的两个变量（参考图来源、视频分辨率档位）；完整参数与环境见文末「复现」。

## 观察

1. **画风完全跟随参考图**：Z-Image 参考产出的视频呈真人 cos 感，Flux2 参考产出的呈赛璐璐动漫。这说明 H3 忠实继承首帧风格，文字提示不改变风格归属；该结论与上游文生图分辨率扫描的结果互相印证。
2. **0.4MP → 0.6MP 的增益集中在背景**：舞台桁架、观众席光斑、蕾丝裙摆纹理明显更清晰，人物主体两档均稳定。这说明高档位分辨率换来的是背景细节，而非人物质量。
3. **角色一致性好**：双马尾、水手服、配色全程保持，无换脸/服装漂移。
4. **运镜与舞步节奏和首帧构图强相关**：同随机种子、同提示词下，两条 0.6MP 成片的起始运镜与舞步安排随参考图的元素布局变化。这说明首帧决定镜头起点，控制开场应调整首帧构图。

## 复现（环境与技术参数）

- 测试环境：H20 GPU，本地服务地址 127.0.0.1:8188（提交命令见下）。
- 模型与模式：MiniMax H3 图生视频（fl2va）。
- 随机种子：seed 91720260。seed 即随机种子，是控制生成过程的随机数取值；四条视频取同一值，可排除随机因素，使差异只来自被对比的变量。
- 采样配置：turbo 8-step / res_multistep / simple。
- 时长与帧率：124 帧 = 5.17s @24fps，成片含原生 AAC 音频。
- 分辨率约束：输出画面宽高均需为 32 的倍数。
- 提交即跑：先把参考图上传 `curl.exe -F "image=@ref_zimg_mp0.6.png" http://127.0.0.1:8188/upload/image`，再 `curl.exe -X POST --data-binary "@workflow_h3_i2v_ref_api.json" http://127.0.0.1:8188/prompt`。换参考图改节点 6 的 image，换视频档位改节点 7 的 width/height。
