# 白水纱旗袍棚拍舞 —— 6 条 take 精剪成一条 16.8s（帧差选切点 + 能量弧重排）

> 成片：[qipao_fine_cut.mp4](qipao_fine_cut.mp4)（16.75s / 544×960 / 含原生音频）
> 在线播放：https://mafeis.github.io/ai-test-lab/#qipao-fine-cut

同一角色、同一棚拍场景、同一支舞，抽了 6 条 5.17s 的 take。本实验要解决的问题不是"能不能生成"，而是**多条 take 怎么剪成一条不像拼贴的片子**：切点选在哪、按什么顺序排、跳变如何量化。

## 结果速览

| 指标 | 原序直拼（对照） | 本实验精剪 |
|------|------------------|------------|
| 片长 | 31.00s | **16.75s** |
| 接点跳变（窗口最大帧差 / 运动基线） | 2.73 ~ 3.31x | **1.63 ~ 2.07x**（收刀处 0.89x） |
| 静态待机体 | 每条 take 首尾各 0.5~1s 全保留 | 剪掉（保留区间内静态占比 0~27%，末两段除外） |
| 重复观感 | 同设定图同提示词的两条 take 直接相邻 | 拆开分居第 1、3 位 |
| 编码次数 | 1 | 1（裁切+叠化+压白在一次 filter_complex 内完成） |

## 素材怎么来的

生成端：ComfyUI（局域网 H20 机器），图生视频工作流 `MiniMaxH3ImageToVideo` + turbo 四步 LoRA（`minimax_h3_fl2v_turbo_4step_v1.2_768p_comfyui_bf16`），文本编码 `qwen3vl_32b_minimax_h3_int8_convrot`。

```
首帧设定图 (input)  ─┐
                    ├─→ ComfyUI /history 清单 ─→ /view 并发下载 ─→ takes/*.mp4
提示词 (两组变体)  ─┘        pull_inventory.mjs      pull_download.mjs
                                                                    │
                              帧差扫描 → 切点预检 → 精剪合成 → 成片验收 ←┘
                              cut_scan     cut_joincheck  cut_build   cut_verify
```

工作流参数：9:16，帧数表达式 `max(5, round(a*24)) ... 140:132,1` → 132 帧 @24fps = 5.17s，24fps，原生音频。

## 精剪方法

四步，全部可复现（[scripts/](scripts)）：

1. **帧差扫描** `cut_scan.mjs`：每条 take 解码成 12fps / 40×52 灰度小帧，做「A 段尾 2.5s × B 段首 2.5s」全有序对穷举，输出每对的最优接点与时刻；同时输出每 0.5s 一格的运动能量曲线，用来标出静态头尾。
2. **能量弧重排**：按"高能段在前、慢镜收尾"排序，并把两条同设定图的重复 take 拆开 —— 顺序 `00273 → 00276 → 00274 → 00278 → 00277 → 00275`。
3. **切点预检** `cut_joincheck.mjs`：把 5 个计划接点的「A 段尾帧 | B 段首帧」并排成一张图（[joins_check.jpg](joins_check.jpg)）目检定刀。数值只负责缩小候选范围，"像素近"不等于"动作连贯"。
4. **精剪合成** `cut_build.mjs`：一次 `filter_complex` 完成 6 段裁切 → 白色补边归一 → 5 组 `xfade`/`acrossfade` → 结尾 0.55s 压白，全片只编码一次。

| 2 | 00276 | 1.390 – 3.530 | 2.14s | 7.40 | 27% |
| 3 | 00274 | 2.220 – 3.940 | 1.72s | 16.56 | 0% |
| 4 | 00278 | 1.560 – 4.505 | 2.94s | 15.72 | 0% |

六段合计 18.01s，5 处叠化重叠扣掉 1.26s → 成片 16.75s。前 4 段能量 7.4~16.6（舞蹈组），后 2 段 4.4/3.0（慢镜组，整段都是微风慢摆）—— 结构是"高能段在前 + 静态镜收势"，不是单调递减。

## 测试方式（度量口径）

成片不能靠"看一遍觉得顺"来验收：0.2s 尺度的跳变判断不可复现，也说不清比上一版好多少。本实验与仓库里其他成片实验用同一套口径：

- **解码**：`ffmpeg` 把视频压成 12fps、40×52 的灰度小帧（每帧 2080 像素，全片 201 帧，穷举扫描在 CPU 上秒级完成）。
- **指标**：相邻帧平均绝对差（MAD）。取镜头内相邻帧差的均值为**运动基线**（本素材 6 条 take 合并基线 = 10.40；成片基线 = 9.89，直拼对照 = 10.57）。
- **接点判据**：接点窗口内最大相邻帧差 ÷ 基线。

| 倍数 | 判读 |
|------|------|
| < 1.0x | 近乎不可见 |
| 1.0 ~ 1.6x | 顺 |
| 1.6 ~ 2.2x | 靠叠化可接受 |
| > 2.2x | 偏跳，需要重选切点 |

- **为什么是这个指标**：SSIM/PSNR 是全局相似度，画面 80% 是纯白背景，人体位移被大面积白色稀释后几乎不动，测不出跳变；40×52 灰度下背景无高频噪声，差值由人体与双马尾的位移主导，且下采样本身就是对生成噪点的低通滤波。
- **人工复核**：数值只用于筛选与横向比较，定刀前看 [joins_check.jpg](joins_check.jpg)（5 组接点并排），定刀后看 [overview_frames.jpg](overview_frames.jpg)（成片 2fps × 36 格连拍，检查节奏与姿态连续性）。

## 结论与边界

1. **顺序比切点值钱**：同一套扫描、同样的算法，只把 take 顺序从生成序改成能量弧，最差接点从 3.11x 降到 2.42x。原序把两条静态慢镜（275）夹在两条高能舞蹈中间，是接点最差的那一刀。
2. **帧差有下界，所以必须留叠化**：舞蹈幅面大 + 纯白背景没有轮廓参照，最优对也只到 1.64x 基线。要求"硬切无缝"在这类素材上不可达；叠化（舞蹈 0.22s / 跨音床 0.35s）负责摊平 1.6~2.4x 的残差。
3. **剪静态段比找切点省片长**：每条 take 首尾是待机和收势（能量 <0.6x 基线），按能量曲线剪掉后 31.0s → 16.75s，观感密度接近翻倍。
4. **两组 take 的音频床不同**（J-pop / 微风），重排后天然形成"音乐段 → 环境音收势"；跨音床的两个接点用更长的 0.35s 溶解，同时兜住画面与声音（`acrossfade` 同偏移）。
5. **纯白棚拍补边必须用白**：黑边在纯白画面里是脏块；补边色属于场景属性，不是默认值。
6. **一次编码**：裁切、归一化幅面、5 组叠化、结尾压白全部放进同一条 `filter_complex`，避免二次编码把叠化区染出色带。
7. **边界**：帧差量不出语义错误（回旋方向相反也可能数值很低），目检不可省；12fps 采样对 24fps 素材有 ±1 帧（约 42ms）量化误差；换非白背景或非舞蹈素材，基线与判读阈值需要重算。

## 复现

```bash
export FFMPEG=ffmpeg FFPROBE=ffprobe      # 不在 PATH 时改成绝对路径
E=experiments/qipao-fine-cut

# 0) 从 ComfyUI 重新取片（可选：仓库已含 takes/）
COMFY_BASE=http://<comfyui-host>:8188 node $E/scripts/pull_inventory.mjs --out /tmp/inv.json
COMFY_BASE=http://<comfyui-host>:8188 node $E/scripts/pull_download.mjs --in /tmp/inv.json --dest $E/takes

# 1~4) 扫描 → 预检 → 合成 → 验收（中间产物落在 $E/_work，已被 .gitignore 忽略）
node $E/scripts/cut_scan.mjs
node $E/scripts/cut_joincheck.mjs
node $E/scripts/cut_build.mjs
node $E/scripts/cut_verify.mjs
```

扫描与验收纯 CPU，全流程在本地几分钟内跑完，不需要 GPU。
