## 4. 执行过程时间线

### 阶段一：程序化建模（6 轮渲染验收）

1. 按技能流程写程序化建模脚本：动漫比例人偶 + 标志性葱绿双马尾 + 无袖清凉装束，Cycles 渲染验证
2. **首次 OOM**：voxel 0.008 重网格 + 二级细分把网格撑到 258MB，16GB 内存被 SIGKILL(137)；
   降级为 voxel 0.014–0.018 / 一级细分 / 64 采样，启用 Metal GPU 后跑通
3. 逐轮 vision_analyze 自检修复：
   - 第 2–3 轮：耳机头带垂在脸前、发圈朝向错误、裙摆棱条刺穿、曝光过强（换 AgX）
   - 第 4 轮：中分刘海露额、领带浮空、裙靴间悬空环
   - 第 5–6 轮：补实心刘海板（精确到眉线不遮眼），最终 **6/6 PASS**

### 阶段二：舞蹈视频（30s）

1. **6 帧预览先行**：验证骨骼绑定 + 编排，再上全片（先廉价比对，后全量）
2. 编舞 8 段与 128 BPM 对齐：弹跳热身 → 波浪手 → 侧滑步摆臂 → 律动指点 → 双跳
   → 360° 旋转（马尾离心外摆）→ 葡萄藤步+拍手 → V 字定格
3. 技术：Empty 骨链刚体层级驱动，双马尾弹簧物理摆动，720 帧关键帧
4. BGM 程序化合成：Am-F-C-G 电子流行，128 BPM 与编舞对齐，tanh 软限幅 + 归一化 0.88
5. 渲染：EEVEE 720×960 @ 24fps，~0.7s/帧，ffmpeg 合成 H.264 + AAC

## 6. 测试结论

**✅ 成功**：两条指令、零人工干预，agent 自主完成建模→修模→绑定→编舞→配乐→渲染合成全流程，
成片时长精确 30.000s，交付物与会话内报告完全一致，后续被用作
[H3 图生视频优化实验](../docs/miku-dance-optimize.md)的原始版本。

**关键经验**：

1. **vision_analyze 抽图自检是无人值守质检的核心**——19 次视觉检查撑起了 6 轮验收闭环
2. **先预览后全量**（6 帧 → 720 帧）大幅节省试错成本
3. 资源受限机器（16GB）上，**降精度重跑**比死磕参数更有效（258MB 网格 → 64MB）
4. 渲染管线要**一次干净重渲**优于多次补渲——文件名污染和 frame 钳制都来自补渲
5. 同一提示词在不同入口（desktop vs api_server）下安全策略执行不一致，值得横向测试
