# H3 分辨率档位扫描 —— 同提示词 0.1 → 0.5 MP 效果与质量对比

同一提示词、同一 seed（91720260）、同一采样配置（8-step turbo / res_multistep），
仅改变分辨率（0.1 → 0.5 百万像素，步进 ~0.1MP），每档 22 帧 ≈ 0.92 秒。

## 快速对比

- 同屏拼条：`comparison_strip.png`（左 → 右 = 0.1 → 0.5MP）
- 同屏视频：`res_comparison.mp4`（5 档并排播放）

## 视觉结论（看拼条从左到右）

1. **0.1MP（256×352）**：整体构图完整但明显发糊，五官细节崩坏，服装纹样糊成色块，只适合快速预览构图与运镜。
2. **0.2MP（384×512）**：人物轮廓和服装层次可辨，脸部仍是模糊的"真人感"，背景灯光有形状但没有光斑质感。
3. **0.3MP（480×640）**：细节明显上来一档，蝴蝶结、腰带结构清晰，开始出现背景景深，性价比档位。
4. **0.4MP（544×736）**：本批次中画风最"动漫"的一档，五官规整，眼神光、发丝高光都出来了。
5. **0.5MP（608×832）**：背景最丰富（雪花光斑、伴舞、拱门结构），服装金属扣件细节最好，码率增长却趋缓（3459→3585 kbps），说明编码器已接近该内容的信息上限。

## 关键发现

- **风格漂移**：同 seed 不同分辨率下 latent 噪声布局完全不同，且没有首帧锚定，各档位生成的不是同一个"角色"——0.4MP 恰好出了标准动漫脸，其余偏写实人像。分辨率本身就是极强的"随机重摇"。
- **质量拐点在 0.3–0.4MP**：低于 0.3MP 面部不可用；0.4MP 起细节收益递减（0.4→0.5MP 耗时 +22%，码率仅 +3.6%）。
- **低成本工作流建议**：用 0.1MP（2.5s/条）批量摇构图和 seed，选中后再用同提示词（换新 seed）在 0.5MP 出成片。
